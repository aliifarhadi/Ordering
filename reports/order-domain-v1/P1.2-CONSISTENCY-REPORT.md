## 2. The defect

`IssueOrderService` accumulated `issuedDocuments` across the traveler loop and called `order.ApplyIssuedDocuments(...)` **only after the whole loop succeeded**. Any early return — Pending, Unknown, or a rejection after an earlier success — persisted traveler A's `ElectronicTicket` while A's `OrderService` still reported "not documented".

That state was also self-perpetuating: a retry derived already-documented services from the persisted tickets, so it correctly skipped traveler A and therefore never repaired A's stale canonical linkage.

`ApplyIssuedDocuments` additionally met the Ticketing time limit and cleared `TimeToLive`, conflating "record one document" with "the ticketing obligation is finished".

## 3. The fix — two separated domain operations

`Order.ApplyIssuedDocuments` is replaced by:

- **`RecordIssuedDocuments(documents)`** — records `ElectronicTicketId` / `TicketCouponId` / document status per service and recomputes the commercial summary. It does **not** touch the ticketing time limit and does **not** advance `CommercialVersion`. Re-recording the same linkage is a no-op, so it is idempotent.
- **`CompleteTicketing(clock)`** — meets the Ticketing time limit and clears `TimeToLive`, and **returns without doing anything unless `IsTicketingComplete()`**, i.e. every service that requires a document is documented.

Supporting predicates `RequiredDocumentServiceIds()`, `DocumentedServiceIds()` and `IsTicketingComplete()` were added to the aggregate. No workflow framework was introduced.

`IssueOrderService` now:

1. **reconciles on entry** — `RecordIssuedDocuments(DocumentEvidenceFrom(persistedTickets))`, an idempotent repair of any historical partial commit (case 5);
2. **records evidence per confirmed ticket immediately**, inside the loop, so the ticket, its coupons, its price links, the `Issued` stock allocation and the `OrderService` linkage all commit in the **same** `OrderingUnitOfWork` save on whichever path returns (Suspend / Reconcile / Finalize);
3. **calls `CompleteTicketing` only in `FinalizeAsync`**, the path reached solely when the outstanding scope is empty.

Provider outcomes are still obtained before the local commit, per the P1.1 intent/recovery pattern; no provider call happens inside a database transaction and no distributed transaction was introduced.

## 4. Second defect found while fixing this

`OrderRepository.AggregateQuery` never `Include`d `TimeLimits` (or `ExternalReferences`). The aggregate therefore loaded with an empty time-limit collection, so `MeetTimeLimit` silently iterated nothing and the ticketing time limit could never actually be met — the new `CompleteTicketing` semantics would have been dead code. Both collections are now included.

## 5. Projection

The order-level `DocumentSummary` facet was derived from ticket status, so one issued ticket made the whole Order look ticketed. It is now derived from **service coverage** and typed `OrderServiceDocumentStatus?`: `null` when nothing requires a document, `Issued` only when every required service is documented, otherwise `Pending`. The details snapshot carries `Document = { Status, RequiredServices, DocumentedServices }` so redisplay is explicit about partial state. The column remains `int`; no migration was required.

## 6. Commercial version

Recording or reconciling document evidence does not advance `CommercialVersion`, and no synthetic commercial mutation is emitted to synchronise the Order with the ticket aggregate. Pinned by test.

Two test-harness corrections were needed: the repair case must use a fresh `DbContext` (a long-lived context returns the cached tracked aggregate and hides the stale row), and the harness gained a stable caller subject so a second worker resumes the same receipt and operation.
