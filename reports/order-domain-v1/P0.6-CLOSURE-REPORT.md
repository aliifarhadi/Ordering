## 3. Resolved findings

1. **Claim fencing (item 1).** Two recovery workers on the same `OrderId` + `OperationId` could both believe they held the current generation — a silent last-writer-wins. Fixed with the existing EF/AeroTech optimistic-concurrency convention (`[Timestamp] RowVersion`), not a new locking framework. Migration `P06ClaimConcurrencyToken`.
2. **Lifecycle composability (item 2).** The receipt now allocates the stable `OperationId`; the servicing-operation store consumes it and is idempotent, so retry and recovery can never create a second economic operation.
3. **Transaction boundary (item 3).** Foundation writes now refuse to run while domain state is pending. The inbox/outbox marker is deliberately still allowed to commit with the effect, preserving the SV-017 atomicity guarantee.
4. **Caller scope (item 4).** Three real defects in what P0 shipped: `principal_type` was parsed as a C# enum name and so **never matched** any machine token; the **selected agency office was dropped**, collapsing two offices into one idempotency scope; and machine principals were keyed on a `client_id` claim Identity does not itself write. All corrected against `E:\Projects\DotAir\IdentityServer` and pinned by adapter-level tests.
5. **Ambient transaction cleanup (item 5).** Both paths now release the query context's transaction association.
6. **CommercialVersion assumptions (item 7).** The passive-expiry invariant was removed; `Order.Expire` and the remark mutators are documented as legacy and non-normative.

## 4. Open item requiring an owner decision

**Review item 6 — internal operation enums in the shared contract project.**

`CommandReceiptStatus`, `ServicingOperationKind` and `ServicingOperationStatus` describe internal Ordering lifecycle and appear in no integration event, but live in `Contracts/AeroTech.Messages/Ordering/Enums`. The review asks for them to move; the owner's standing rule is that **all** enums live there. The move was attempted in this session, the owner intervened, and it was **fully reverted** — the code is exactly as the owner's convention requires.

One decision needed: keep the standing convention, or make a narrow exception for internal lifecycle vocabulary that never crosses the wire. Until then this exit-gate item stays open by instruction, not by oversight.
