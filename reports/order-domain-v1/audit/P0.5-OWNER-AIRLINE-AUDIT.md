## 2. What was NOT done, and why

| Rejected option | Reason |
|---|---|
| Hardcode `1` | forbidden; and it is exactly the defect BD-1a exists to remove |
| Read the Core database directly | crosses a service boundary |
| Copy Core tables into Ordering | Ordering projects the **minimum** field set, not the Core model |
| Put `HomeAirlineId` into the JWT | the owner ruled it is not a caller-selected context |
| Infer from `AirlineOfficeId`, customer, seller, or validating/marketing/operating carrier | all forbidden; pinned by automated tests |
| A generic multi-tenant framework | out of scope and explicitly forbidden |
| A temporary fallback | forbidden; the provider fails closed instead |
| Create a new Core contract / raise a handoff | unnecessary — the contract in §1.2 already exists |
| Change `BaseIntegrationEvent.TenantId` | explicitly out of scope; `TenantId` and `OwnerAirlineId` stay semantically distinct |

## 3. Implementation

### 3.1 Projection through the existing reference-data mechanism

| File | Role |
|---|---|
| `ReferenceData/ReadModels/OperatorSettingsReadModel.cs` | `Id`, `ScopeKey`, `HomeAirlineId`, `LastUpdateTime` — **minimum only**; `DefaultCurrencyId`, `DefaultLanguageCode` and `DefaultTimeZoneId` are deliberately not projected |
| `ReferenceData/ReadModels/OperatorScopeKey.cs` | `HomeOperator = "HOME_OPERATOR"`, mirroring Core's constant |
| `ReferenceData/Core/Wire/CoreDtos.cs` | `OperatorSettingsDto : ISyncSourceDto<long>` |
| `ReferenceData/Core/ICoreClient.cs`, `CoreClient.cs` | `GetOperatorSettingsAsync` on route `v1/OperatorSettings`; the customer and operator reads were factored onto one private `GetAsync<T>` so the envelope/error handling is shared, not duplicated |
| `ReferenceData/Syncing/OperatorSettingsSyncer.cs` | `ReferenceSyncerBase<OperatorSettingsReadModel, OperatorSettingsDto, long>`, resource key `OperatorSettings` |
| `ReferenceData/Persistence/ReferenceDbContext.cs` | table `ReferenceData.OperatorSettings`, **unique index on `ScopeKey`** |
| `ReferenceData/Api/ReferenceSyncController.cs` | `POST Syncer/v{version}/OperatorSettings`, matching the five existing syncer endpoints |
| Migration | `P05OperatorSettingsProjection` (ReferenceData context), applied to the local dev database |

The `ReferenceData` project remains **fully isolated** — it still has zero project references, so the CLAUDE.md "own schema/context, zero domain coupling" rule is intact.

### 3.2 Trusted provider

`Domain/_Shared/Contracts/IHomeOperatorProvider.cs` declares the port; `ServiceHost/OperatorContext/ReferenceDataHomeOperatorProvider.cs` implements it by reading the local projection by `ScopeKey`.

Placement rationale: `ReferenceData` has no project references and must keep none, so it cannot implement a `Domain`-declared port. `ServiceHost` is the only project that sees both, and it is already the home of this repository's other trusted-context adapter, `ClaimsCallerContext` — which itself mirrors where Aegis and Core put theirs. The port lives in `Domain` exactly like `IOrderRepository`.

**Fail-closed:** a missing row, or a non-positive `HomeAirlineId`, throws `ExceptionFactory.HomeOperatorNotProvisioned` (**2710**, HTTP 500). There is no `0`, no `1`, no `TenantId`, no carrier fallback.

**No per-command Core call:** the provider reads one indexed row from the local `ReferenceData` projection. Core is contacted only by the syncer, on the existing operator-triggered `Syncer/v1/OperatorSettings` endpoint — the same cadence as every other reference resource. No additional cache layer was introduced; a single-row lookup on a unique index is cheaper than the invalidation problem a cache would add.

### 3.3 Wiring into the P0 foundation (and no further)

| File | Role |
|---|---|
| `Domain/_Shared/Operations/Contracts/ICommandReceiptStore.cs` | `AcquireAsync(operationName, idempotencyKey, requestHash)` → `CommandReceiptResult` |

Neither entry point accepts an owner, tenant, carrier, seller, agency or office parameter — that is enforced by test, not just by review. **No P1 business flow was added**: nothing creates an Order, requests payment, issues a document or calls a provider.

### Follow-up recorded, not silently fixed

- **F-7 is now decoupled from BD-1a.** The earlier P0 record listed the hardcoded
  `IntegrationEventOptions.TenantId = 1` as gated by BD-1a. The owner has since ruled `TenantId` a
  separate platform concern, so F-7 remains open on its own and was deliberately left untouched here.
- **Operational prerequisite:** `POST Syncer/v1/OperatorSettings` must run at least once per environment
  before any operation requiring `OwnerAirlineId` can succeed. Until it does, those operations fail closed
  with 2710 — which is the intended behaviour, not a defect.
- Core's `ICallerContext` still defines local `CallerContextType`/`CallerPrincipalType` enums where Aegis
  uses the shared contract enums (recorded in the P0 audit §10.1). Core-side debt; not touched.
